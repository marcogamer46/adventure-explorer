The big idea

What are you actually building?

The challenge

A world exists: a grid of floor (.) and walls (#), with a start tile and an exit tile. The explorer starts on the start tile. Your job is to write the code that decides what it does next, one turn at a time, until it reaches the exit.

Your six pieces

You write two data classes (information), two generators (world-building), and two brain classes (decisions). The workbench provides the map, the rules, and the recording — it checks your code and shows you exactly what happened on every turn.

Why it matters

This is object design + state + making good choices in one project. You'll learn to keep data and behavior separate, write deterministic generators from a seed, and make decisions from a read-only snapshot — the same shape as real game AI, agents, and robotics loops.

Ground rules

How the world works

Start (S) Exit (E) Artifact Enemy Floor Wall
⊕

Position

An (row, column) pair. Rows and columns start at 0 — the top-left is Position(0, 0), and moving east increases the column.

▦

Terrain

A rectangle of rows. . is walkable floor, # is a wall. is_traversable(pos) tells you if a position is in-bounds and on floor.

◈

Start & exit

Two separate coordinates — not letters drawn on the map. The explorer starts at S and finishes only by returning the EXIT action while standing on E.

☷

Occupancy ≠ floor

A tile can be floor and hold an enemy. Traversable tells you about geometry; your controller must also think about what's currently occupying the tile.

Your code

The six components you build

Three are pure data (fields). Three are behavior (methods). Keep them separate — the workbench hooks them together.

Data
🧍

Character

The explorer's identity tag.

Character(agent_id)
@property agent_id -> str

Just carries an id. It does not store the position or move itself — that's the controller's job.

Data
💎

Artifact

A reward sitting on a tile.

Artifact(artifact_id,
         position, value)
@property artifact_id / position / value

Walking onto it does not collect it — you must return COLLECT with its id. It doesn't award its own points.

Data
👹

Enemy

A static blocker on a tile.

Enemy(enemy_id,
       position, encounter_penalty)
@property enemy_id / position /
        encounter_penalty

No attack, health, or dice. Engaging it adds its penalty once, then it's cleared. You can't just walk through it.

Logic
🧠

AgentController

The explorer's brain.

AgentController()
choose_action(state, agent_id)
        -> WorldAction

Reads the snapshot, returns exactly one action. It may keep private planning state during a run — a fresh controller is built for every run.

Logic
🗺️

TerrainGenerator

Builds the floor geometry.

TerrainGenerator()
generate_terrain(specification, seed)
        -> Terrain

Returns a Terrain from a spec + seed. Same inputs ⇒ same output. It knows nothing about start, exit, or entities.

Logic
🏰

LevelGenerator

Assembles the full world.

LevelGenerator(terrain_generator)
generate_level(specification, seed)
        -> LevelDefinition

Uses an injected terrain generator, picks valid endpoints, places the character and entities, and returns the initial world. Never a solution.

The game loop

One turn at a time

1
📊

Snapshot arrives

The runtime hands your controller a read-only WorldSnapshot: the level, current position, turn count, what's been collected/defeated, and allowed actions.

→
2
🧠

You decide

Your choose_action reads the snapshot and returns exactly one WorldAction — e.g. MOVE_EAST or COLLECT with a target id.

→
3
⚖️

Runtime validates

The runtime checks the action against the rules — is it legal, in bounds, the right target? If not, the run ends immediately.

→
4
🔁

Next snapshot

The action is applied, the turn advances, and a fresh snapshot is sent back. You always read the new snapshot — don't assume your last move succeeded.

The loop repeats until the explorer returns EXIT on the exit tile, or the run hits a limit. You never move sprites or mutate state yourself — you only intend.

The vocabulary

What an action can be

MOVE_NORTH / SOUTH / WEST / EAST

Move one tile in that direction — only if the destination is in-bounds floor and not occupied by an undefeated enemy at action start.

COLLECT

Target an artifact on the tile you're standing on. Awards its value once, keeps you in place. You must be on the tile.

ENGAGE

Target a static enemy on an adjacent tile. Adds its penalty once and clears it — you stay where you are.

WAIT

Consume a turn without moving. Useful for timing past patrols; a later patrol step can still collide.

EXIT

Return this while standing on the exit tile. Arriving is not finishing — you must explicitly EXIT, and it counts as one accepted action.

INTERACT disabled

Defined in the enum but turned off in the public gameplay. Don't return it.

How scoring works

Keep the total cost low — that's the score.

actions + penalties = total cost

Every accepted action (moves, COLLECT, ENGAGE, EXIT, WAIT) counts as 1. Encounter penalties are added on top. Collecting an artifact adds its points, so a 20-point reward that costs one extra action nets +15 if the penalty rate is 5.

💡 Classic trap: a reward can cost more to collect than it's worth. Always compare route costs before deciding.

See it in code

A minimal controller

This handles the straight path: compare positions, move toward the exit, and EXIT when you arrive. It's a starting skeleton, not the final answer.

src/student/controller.py 
# -*- coding: utf-8 -*-
from src.api import WorldAction, WorldActionType

class AgentController:
    def choose_action(self, state, agent_id):
        pos = state.agent_position
        exit_pos = state.level.exit

        # 1) Already standing on the exit → leave.
        if pos == exit_pos:
            return WorldAction(WorldActionType.EXIT)

        # 2) Move east if the exit is to the east.
        if pos.column < exit_pos.column:
            return WorldAction(WorldActionType.MOVE_EAST)

        # 3) Otherwise move toward it vertically.
        if pos.row < exit_pos.row:
            return WorldAction(WorldActionType.MOVE_SOUTH)
        return WorldAction(WorldActionType.MOVE_NORTH)

🟢 Why this works: it only chooses legal moves toward the exit and explicitly EXITs — a hard-coded "move east forever" would miss the exit requirement and break on any other layout.

Cheat sheet

API quick reference

Everything is imported from src.api. These are the names you'll touch most.

Provided values

  • Position(row, column) — a coordinate; .manhattan_distance(other)
  • Terrain(terrain_rows) — .rows, .columns, .is_traversable(pos)
  • LevelDefinition — terrain, start, exit, character, artifacts, enemies, patrols
  • WorldSnapshot — current state passed to your controller
  • WorldAction(type, *, target_id=None) — the action you return; WorldAction.wait()
  • TerrainGenerationSpec / LevelSpecification — the requests the generators receive

Snapshot fields

  • level — the initial world (still present after changes)
  • agent_position — where the explorer is now
  • turn — count of accepted actions so far
  • collected_artifact_ids / defeated_enemy_ids
  • allowed_actions — the action types currently allowed
  • enemy_observations — current enemy positions (important for patrols)
  • base_points, deduction_rate, baseline_cost, max_turns, deadline_turn

Action rules (reminder)

  • Moves require in-bounds, unoccupied floor.
  • COLLECT targets an artifact on your tile.
  • ENGAGE targets an adjacent static enemy.
  • EXIT only on the exit tile; counts as an action.
  • Returning a bare string like "east" or None is malformed — always return a WorldAction.

Need exact signatures? The workbench's Help and the bundled API_REFERENCE.md have the full detail.
